# HTTP / CLI 接口清单

默认 API 根为 `http://127.0.0.1:3001/api`。Agent HTTP 写接口供本地 `workbench` CLI 使用；WebUI 对 Agent 运行面只读。

## Project / Task / Files

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/api/projects` | 列表 / 创建 Project |
| GET/PUT/DELETE | `/api/projects/:id` | Project 详情 / 更新 / 删除 |
| GET/POST | `/api/projects/:projectId/tasks` | Task 列表 / 创建 |
| GET/PUT/DELETE | `/api/tasks/:taskId` | Task 详情 / 元数据 / 删除 |
| PUT | `/api/tasks/:taskId/workflow` | 替换独立 Workflow 快照；支持 `expectedWorkflowSha256` |
| PUT | `/api/tasks/:taskId/root` | 为旧 Task 绑定或创建稳定根 |
| GET | `/api/projects/:projectId/files` | 浏览 Project 工作根内文件 |
| GET | `/api/projects/:projectId/files/read` | 读取文本文件 |
| POST | `/api/projects/:projectId/files/mkdir` | 在 Project 工作根内建目录 |
| GET/PUT | `/api/tasks/:taskId/progress/...` | 核心 step 进度、笔记、命令与文件引用 |

Task 创建只建立 Task 根，不创建 Workflow Stage 子目录。

## Workflow / Research Plan / Experience

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/workflows` / `/all/full` / `/:id` | 模板摘要、完整列表、详情 |
| PUT | `/api/workflows/:id` | 保存模板 |
| POST | `/api/workflows/:id/reset` | 重置到内置默认 |
| GET/POST | `/api/research-plans` | 列表 / 在 Project 创建 Markdown |
| POST | `/api/research-plans/import` | 导入 Markdown |
| GET/PUT/DELETE | `/api/research-plans/:id` | 元数据详情 / 更新 / 删除或归档保护 |
| GET/PUT | `/api/research-plans/:id/content` | 内容与 SHA-256 / 原子保存 |
| GET/POST | `/api/experiences` | 搜索 / 人工创建经验 |
| GET/PUT/DELETE | `/api/experiences/:id` | 详情 / 修订 / 删除 |
| POST | `/api/experiences/codex-capture` | Codex 幂等捕获 candidate |

## Agent Context 与 Run

所有路径以 `/api/agent/v1` 为前缀。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/context/tasks/:taskId` | `AgentContext` schema v3；包含 Run monitor，即使有 blocker 也返回完整记录 |
| GET | `/execution-contract` | 通用 capability 与恢复规则 |
| POST | `/runs` | 创建 Task Spec draft |
| GET | `/runs/:runId` | Run 与 Task Spec（含两个 SHA-256） |
| POST | `/runs/:runId/confirm` | Codex 对话中的一次 Envelope 确认 |
| PUT | `/runs/:runId/working-plan` | Codex 自主更新 Working Plan |
| POST | `/runs/:runId/envelope-revisions` | 解决 researcher item 并确认新版 Envelope |
| POST | `/runs/:runId/complete` | 研究者确认完成 |
| POST | `/runs/:runId/terminate` | 终止 Run |
| GET/POST | `/runs/:runId/events` | 读取/追加 Event |

创建 Run 请求：

```json
{
  "taskId": "task-id",
  "researchPlanId": "plan-id",
  "taskSpec": {
    "schemaVersion": 1,
    "objective": "...",
    "confirmedEnvelope": {},
    "workingPlan": {}
  },
  "idempotencyKey": "stable-key"
}
```

`confirm`、Envelope revision、Run completion 与 researcher Pending resolution 必须声明 `source=codex_conversation`。Web 不调用这些接口。

## Pending Item

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/pending-items` | 按 run/project/task/audience/status 筛选 |
| GET/POST | `/runs/:runId/pending-items` | Run 队列 / 创建 |
| POST | `/pending-items/:itemId/resolve` | 解决或忽略 |

`audience=codex` 用于操作与恢复；`audience=researcher` 用于材料科学决定或 Envelope 扩展。

## Action / Artifact / Evidence

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/runs/:runId/actions` | 列表 / 记录非执行或自定义 Action |
| POST | `/runs/:runId/executable-actions` | 从 capability spec 创建带输入快照的 `ready` Action |
| GET | `/actions/:actionId` | Action + Artifacts + Evidence + Jobs |
| POST | `/actions/:actionId/execute` | 在已确认 Envelope 内执行 |
| POST | `/actions/:actionId/status` | 受状态机约束的状态更新 |
| GET | `/runs/:runId/artifacts` | Run Artifacts |
| POST | `/actions/:actionId/artifacts` | 登记 Artifact |
| POST | `/artifacts/:artifactId/validity` | 标记 valid/suspect/invalid/superseded |
| GET | `/runs/:runId/evidence-checks` | Run validator 记录 |
| POST | `/actions/:actionId/evidence-checks` | 登记 validator 结果 |
| GET | `/evidence-library` | project/task/location/checkStatus/validity/search 筛选 |

Executable Action 请求只需 Stage、capability、task-specific spec 和幂等键；host 与 Task remote root 由确认的 HPC profile 和 Task binding 派生。没有逐 Action authorize 接口。

## 远程观察

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/remote/jobs/:jobId/status` | 查询已记录 Job |
| POST | `/remote/jobs/:jobId/logs` | 读取日志 |
| POST | `/remote/jobs/:jobId/reconcile` | 对账，尤其是 `submission_uncertain` |
| GET | `/monitor/guard` | 检查是否有活跃 Job 未绑定 Scheduled Task |
| GET | `/runs/:runId/monitor` | 读取 Run monitor |
| POST | `/runs/:runId/monitor/attach` | 绑定当前任务 automation reference 与 cadence |
| POST | `/runs/:runId/monitor/tick` | 只对账已到 `next_check_at` 的 Job |
| POST | `/runs/:runId/monitor/pause` | 暂停 monitor；活跃 Job 会再次触发 guard |

创建/上传/下载/提交/取消只能通过 executable Action；不存在 Task 级直通远程写 API。

## CLI 对应

主要命令：

```text
workbench doctor
workbench context --task <id> --allow-blocked --pretty
workbench run draft|show|confirm|working-plan|revise-envelope|complete|terminate
workbench action prepare|record|execute|show|list|status
workbench pending list|create|resolve
workbench artifact register|validity|list
workbench evidence check|list
workbench event append
workbench experience search|capture
workbench remote status|logs|reconcile
workbench monitor guard|show|attach|tick|pause
```

Exit code：`0` 成功、`2` 参数错误、`3` API 拒绝、`4` 记录边界/待处理状态阻塞、`5` 无法连接本地服务。

## 错误与安全

Agent 错误响应为 `{ error, code, details? }`。路径必须是根内安全相对路径；HPC alias 必须登记；远程写必须使用 Task root；LSF 资源受 Envelope 限制。服务默认只绑定本机；远程 capability 还需要显式环境开关。
