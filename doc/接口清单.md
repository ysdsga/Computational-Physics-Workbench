# DFT+DMFT Workbench 接口清单

> 最后核对：2026-08-15（Codex action/evidence/conclusion 与只读 Web）
> Base URL: `http://127.0.0.1:3001/api`
> 所有请求/响应均为 JSON 格式

---

## 1. 工作流模板

### GET /api/workflows
获取数据库中的工作流模板元数据列表。

**响应** `200 OK`
```json
[
  {
    "id": "dft-dmft-oneshot",
    "name": "One-shot DFT+DMFT",
    "description": "单次 DMFT 计算，不自洽更新电荷密度"
  }
]
```

### GET /api/workflows/all/full

获取所有完整模板，响应包含每个模板的 `stages` 和 `steps`。前端 `WorkflowContext` 启动时调用此接口。

### GET /api/workflows/:id

获取单个完整模板。数据库没有该 ID 时，后端会尝试使用同 ID 的内置默认模板。

### PUT /api/workflows/:id

保存完整模板。请求体必须包含数组 `stages` 和 `steps`，可选包含 `name`、`description`。模板存在时更新，不存在时创建。

### POST /api/workflows/:id/reset

将数据库中的模板恢复为 `src/data/workflows.ts` 中的同 ID 内置默认值。没有对应内置模板时返回 `404`。

> 现役模板以 `workflow_templates` 表为准；源码新增的内置模板会按 ID 增量播种，已有同 ID 模板不会被覆盖；重置操作恢复源码默认值。

当前内置 One-shot 模板包括：通用 QE/Wannier90/TRIQS、非磁 QE/W90/自发磁性 DMFT、WIEN2k/dmftproj/TRIQS。

## 2. 项目管理

### GET /api/projects
获取所有项目列表。

**响应** `200 OK`
```json
[
  {
    "id": "proj-1783599367824-r6jap2",
    "name": "V2O3 电子结构研究",
    "description": "研究 V2O3 的电子关联性质",
    "material": "V2O3",
    "working_dir": "D:/projects/v2o3",
    "created_at": "2026-07-09T12:16:07.824Z",
    "updated_at": "2026-07-09T12:16:07.824Z"
  }
]
```

### GET /api/projects/:id
获取单个项目详情（含任务数）。

**路径参数**

| 参数 | 类型 | 说明 |
|------|------|------|
| `id` | string | 项目 ID |

**响应** `200 OK`
```json
{
  "id": "proj-...",
  "name": "V2O3 电子结构研究",
  "description": "...",
  "material": "V2O3",
  "working_dir": "D:/projects/v2o3",
  "hpc_config": null,
  "created_at": "...",
  "updated_at": "...",
  "task_count": 3
}
```
**错误** `404` — `{"error": "Project not found"}`

### POST /api/projects
创建项目。

**请求体**
```json
{
  "name": "V2O3 电子结构研究",      // 必填
  "description": "研究 V2O3...",    // 可选
  "material": "V2O3",              // 可选
  "working_dir": "D:/projects/v2o3" // 可选
}
```

**响应** `201 Created` — 返回完整项目对象
**错误** `400` — `{"error": "Name is required"}`

### PUT /api/projects/:id
更新项目（部分更新，未传字段保持不变）。

**请求体**（所有字段可选）
```json
{
  "name": "新名称",
  "description": "新描述",
  "material": "新材料",
  "working_dir": "D:/new/path",
  "hpc_config": "{...}"              // 可选，HPC 配置 JSON 字符串
}
```

**响应** `200 OK` — 返回更新后的项目对象
**错误** `404` — `{"error": "Project not found"}`

### DELETE /api/projects/:id
删除项目（级联删除其下所有任务、进度、文件关联）。

**响应** `200 OK` — `{"success": true}`
**错误** `404` — `{"error": "Project not found"}`

有研究运行引用时返回 `409 RUN_HISTORY_PROTECTED`，只能通过 `PUT` 把 `status` 改为 `archived`。

## 3. 任务管理

### GET /api/projects/:projectId/tasks
获取项目下的所有任务。

**路径参数**

| 参数 | 类型 | 说明 |
|------|------|------|
| `projectId` | string | 项目 ID（从父路由获取） |

**响应** `200 OK`
```json
[
  {
    "id": "task-...",
    "project_id": "proj-...",
    "name": "V2O3 顺磁性 one-shot DMFT",
    "description": "",
    "workflow_id": "dft-dmft-oneshot",
    "workflow": { "id": "dft-dmft-oneshot", "name": "...", "stages": [], "steps": [] },
    "status": "active",
    "created_at": "...",
    "updated_at": "..."
  }
]
```

### POST /api/projects/:projectId/tasks
在项目下创建任务。

**请求体**
```json
{
  "name": "V2O3 顺磁性 one-shot DMFT",    // 必填
  "description": "首次尝试",               // 可选
  "workflow_id": "dft-dmft-oneshot",      // 必填
  "status": "active"                       // 可选，默认 active
}
```

**响应** `201 Created` — 返回完整任务对象，其中 `workflow` 是创建时复制的独立工作流
**错误**
- `400` — `{"error": "Name is required"}` 或 `{"error": "Workflow ID is required"}`
- `404` — `{"error": "Project not found"}`

如果项目设置了 `working_dir`，后端分配稳定 `task_root_rel`，并创建 `{task_root_rel}/{stageId}/` 阶段目录；任务改名不会改目录。

### PUT /api/tasks/:taskId/root

为 unresolved 旧任务选择项目目录内的稳定任务根。请求体：`{"task_root_rel":"existing-dir","create":false}`。绝对路径、`..`、项目根、逃逸符号链接和已被其他任务占用的根会被拒绝；已经解析的任务返回 `409 TASK_ROOT_ALREADY_RESOLVED`，不能借此接口改换目录。

### GET /api/tasks/:taskId
获取单个任务详情（含步骤进度）。

**响应** `200 OK`
```json
{
  "id": "task-...",
  "project_id": "proj-...",
  "name": "...",
  "workflow_id": "dft-dmft-oneshot",
  "workflow": { "id": "dft-dmft-oneshot", "name": "...", "stages": [], "steps": [] },
  "status": "active",
  "created_at": "...",
  "updated_at": "...",
  "progress": [
    {
      "id": "sp-...",
      "task_id": "task-...",
      "step_id": "prep-01",
      "status": "completed",
      "notes": "目标已确定",
      "updated_at": "..."
    }
  ]
}
```

### PUT /api/tasks/:taskId/workflow
保存当前任务自己的工作流。请求体为完整工作流对象（`name`、`description`、`stages`、`steps`）；只更新该任务，不修改来源模板或其他任务。新增阶段会补建对应阶段目录，删除阶段不会删除已有目录、计算文件或历史进度。

**响应** `200 OK` — 返回保存后的任务工作流

**错误**
- `400` — 工作流结构无效、阶段/步骤 ID 重复，或步骤引用了不存在的阶段
- `404` — 任务不存在

### PUT /api/tasks/:taskId
更新任务（部分更新）。

**请求体**（所有字段可选）
```json
{
  "name": "新名称",
  "description": "新描述",
  "status": "completed"
}
```

**响应** `200 OK` — 返回更新后的任务对象

### DELETE /api/tasks/:taskId
删除任务（级联删除其下所有进度和文件关联）。

**响应** `200 OK` — `{"success": true}`

有研究运行引用时返回 `409 RUN_HISTORY_PROTECTED`，只能归档。

## 4. 步骤进度

### GET /api/tasks/:taskId/progress
获取任务的所有步骤进度（含关联文件）。

**响应** `200 OK`
```json
[
  {
    "id": "sp-...",
    "task_id": "task-...",
    "step_id": "dft-02",
    "status": "completed",
    "notes": "SCF 收敛到 10^-8",
    "updated_at": "...",
    "files": [
      {
        "id": "sf-...",
        "step_progress_id": "sp-...",
        "file_path": "D:/projects/v2o3/dft/scf.in",
        "file_name": "scf.in",
        "description": "SCF 输入文件",
        "is_remote": 0,
        "created_at": "..."
      }
    ]
  }
]
```

> 注：只返回有记录的步骤。未操作过的步骤不会出现在列表中，前端视为 `pending`。

### PUT /api/tasks/:taskId/progress/:stepId
更新（或创建）步骤的进度。Upsert 语义。

**路径参数**

| 参数 | 类型 | 说明 |
|------|------|------|
| `taskId` | string | 任务 ID |
| `stepId` | string | 步骤 ID（如 `dft-02`） |

**请求体**（所有字段可选，COALESCE 更新）
```json
{
  "status": "completed",    // pending | in_progress | completed | skipped
  "notes": "SCF 收敛了",    // 步骤笔记
  "commands": ["pw.x -in scf.in"], // 可选，自定义命令数组
  "lsf_script": "#BSUB ..."         // 可选，自定义 LSF 脚本
}
```

**响应** `200 OK` — 返回更新后的 step_progress 对象

**错误** `400` — `{"error": "file_path and file_name are required"}`

## 6. 文件仓库（文件系统操作）

### GET /api/projects/:projectId/files?path=
浏览项目工作目录下的文件和子目录。

**查询参数**

| 参数 | 类型 | 说明 |
|------|------|------|
| `path` | string | 子目录相对路径（相对于 working_dir），可选，默认为根目录 |

**响应** `200 OK`
```json
{
  "entries": [
    {
      "name": "dft",
      "isDirectory": true,
      "size": 0,
      "modified": "2026-07-09T12:00:00.000Z",
      "relativePath": "dft"
    },
    {
      "name": "scf.in",
      "isDirectory": false,
      "size": 2048,
      "modified": "2026-07-09T12:30:00.000Z",
      "relativePath": "scf.in"
    }
  ],
  "currentPath": "",
  "exists": true
}
```

> 目录排在文件前面，按名称排序。

**错误**
- `400` — `{"error": "Project has no working directory set"}`
- `403` — `{"error": "Access denied: path outside working directory"}`（路径安全检查）
- `500` — `{"error": "Failed to read directory: ..."}`

### POST /api/projects/:projectId/files/mkdir
在项目工作目录下创建子目录（支持递归创建）。

**请求体**
```json
{
  "path": "dft",          // 父目录相对路径，可选，默认根目录
  "name": "scf_output"    // 新目录名，必填
}
```

**响应** `201 Created`
```json
{
  "success": true,
  "path": "dft/scf_output"
}
```

### GET /api/projects/:projectId/files/read?path=
读取文本文件内容（限 1MB 以内）。

**查询参数**

| 参数 | 类型 | 说明 |
|------|------|------|
| `path` | string | 文件相对路径（相对于 working_dir），必填 |

**响应** `200 OK`
```json
{
  "content": "&control\n  prefix='v2o3'\n  ...",
  "name": "scf.in",
  "size": 2048
}
```

**错误**
- `400` — `{"error": "Path is a directory"}`
- `413` — `{"error": "File too large (max 1MB)"}`
- `403` — `{"error": "Access denied"}`
- `500` — `{"error": "Failed to read file: ..."}`

## 8. 研究方案（v3 · 项目目录文件型）

> **v3 (2026-08-09)**：方案正文不入库，正文唯一源是所属项目 `working_dir/<file_name>`。
> 本组接口同时管理"文件"与"元数据记录"。

| 方法 | 路径 | 作用 |
|------|------|------|
| GET | `/api/research-plans` | 列表（扫目录+自动补元数据） |
| GET | `/api/research-plans/:id` | 单条元数据 |
| GET | `/api/research-plans/:id/content` | 读 .md 正文 |
| PUT | `/api/research-plans/:id/content` | 写 .md 正文 |
| POST | `/api/research-plans` | 新建（建文件 + 元数据） |
| POST | `/api/research-plans/import` | 导入（复制/写入文件 + 元数据） |
| PUT | `/api/research-plans/:id` | 改元数据（不改正文） |
| DELETE | `/api/research-plans/:id` | 删元数据（默认同时删文件） |

> 路由顺序：`POST /import` 必须在 `GET/PUT/DELETE /:id` 之前注册。

### GET /api/research-plans
列表扫描各项目 `working_dir` 下的 `*.md`，对 DB 无记录的文件自动补元数据（title=文件名去 `.md`）。旧的根目录 `research-plans/` 不再扫描。

**查询参数**（可选）：`projectId` / `status` / `search`（在 title/tags 搜）

**响应** `200 OK`
```json
[
  {
    "id": "rp-...",
    "file_name": "v2o3_plan.md",
    "title": "v2o3 plan",
    "project_id": "proj-...",
    "linked_task_ids": "[]",
    "status": "draft",
    "tags": "[]",
    "created_at": "...",
    "updated_at": "...",
    "missing": false
  }
]
```
> `missing: true` 表示文件已被外部删除但 DB 记录还在。

### GET /api/research-plans/:id
单条元数据，响应同列表项。

### GET /api/research-plans/:id/content
读 Markdown 正文（限 10MB）。

**响应** `200 OK`
```json
{ "content": "# 标题\n\n正文...", "size": 12345, "modified": "2026-07-28T..." }
```
**错误** `404` — 方案或文件不存在

### PUT /api/research-plans/:id/content
写 Markdown 正文，同时刷新 `updated_at`。

**请求体** `{ "content": "# 新内容..." }`
**响应** `200 OK` — `{ "success": true, "updated_at": "..." }`

### POST /api/research-plans
新建方案：生成安全文件名（冲突加时间戳后缀）+ 写入文件 + INSERT 元数据。

**请求体**
```json
{
  "title": "V2O3 方案",                      // 必填
  "content": "# V2O3 方案\n\n...",          // 可选，默认 "# {title}\n\n"
  "project_id": "proj-...",                  // 必填，且项目须配置有效 working_dir
  "status": "draft",                         // 可选
  "tags": ["V2O3"],                          // 可选
  "linked_task_ids": ["task-..."]            // 可选
}
```
**响应** `201 Created` — 返回完整元数据对象
**错误** `400` — 标题、项目或项目工作目录无效

### POST /api/research-plans/import
从本机路径复制或直接写入 Markdown 内容。

**请求体（两种模式二选一）**
```json
// 模式 A：从本机路径复制
{ "sourcePath": "D:\\docs\\plan.md", "fileName": "imported.md", "project_id": "proj-..." }
// 模式 B：粘贴内容
{ "content": "# 粘贴的方案...", "fileName": "pasted.md", "project_id": "proj-..." }
```
**响应** `201 Created` — 返回完整元数据对象

### PUT /api/research-plans/:id
更新元数据（不改正文）。所属项目不可通过此接口变更。

**请求体**
```json
{
  "title": "新标题",                    // 可选
  "linked_task_ids": ["task-..."],     // 可选
  "status": "active",                  // 可选
  "tags": ["V2O3", "DMFT"]             // 可选
}
```
**响应** `200 OK` — 返回更新后的元数据对象

### DELETE /api/research-plans/:id
删除方案。

**查询参数**（可选）：`deleteFile=false` 时仅删元数据，保留磁盘文件（默认 `true` 同时删文件）。

**响应** `200 OK` — `{"success": true}`
**错误** `404` — `{"error": "Not found"}`

有研究运行引用时返回 `409 RUN_HISTORY_PROTECTED`，方案文件和元数据均不会删除。

## 9. 研究合同

- `GET /api/research-plans/:id/contract`：读取 YAML 原文、校验结果、合同哈希、当前方案哈希和 drift。
- `POST /api/research-plans/:id/contract/initialize`：按当前方案生成最小合同；默认不覆盖已有合同。
- `PUT /api/research-plans/:id/contract`：校验并原子替换合同；`expectedPlanSha256` 可防止覆盖并发更新。

合同固定保存到 `<project.working_dir>/.workbench/contracts/<research-plan-id>.yaml`，且 `approvedPlan.path/sha256` 必须绑定当前方案。

## 10. Agent API

Base path：`/api/agent/v1`。

| 方法与路径 | 作用 |
|---|---|
| `GET /context/tasks/:taskId` | 返回 `AgentContextV1`；缺运行或合同等仍返回 `blockers[]` |
| `POST /runs` | 启动运行并原子创建首个上下文版本和事件 |
| `GET /runs/:runId` | 读取运行 |
| `POST /runs/:runId/revise` | 提交候选方案/合同；边界内采用，扩权返回 `202` 评价请求 |
| `POST /runs/:runId/terminate` | 终止运行并写 decision event |
| `POST /runs/:runId/adopt-policy` | 研究者把当前 active policy 显式写入新上下文版本 |
| `GET/POST /runs/:runId/events` | 游标分页读取或幂等追加事件 |
| `POST /runs/:runId/conclusions` | 记录 Codex 对话中研究者明确确认的结论；重新校验本地 artifact 哈希 |
| `POST /runs/:runId/experience-promotions` | 把当前 context 的 researcher conclusion 提升为不可变 Experience |
| `GET/POST /runs/:runId/actions` | 查询或由 Codex 提出绑定 context、step、manifest 哈希和幂等键的动作 |
| `GET /execution-contract` | 返回材料无关 capability、spec 字段和执行边界 |
| `POST /runs/:runId/executable-actions` | 根据 Codex 提供的 capability spec 建立输入/脚本/资源快照并提出 immutable action |
| `GET /actions/:actionId` | 查询动作及其 job、artifact、evidence 明细 |
| `POST /actions/:actionId/authorize` | 记录 Codex 对话中的研究者授权摘要；同时校验 context 和 immutable manifest 哈希 |
| `POST /actions/:actionId/execute` | 仅执行已授权、无 context/input drift 的通用 capability manifest |
| `POST /actions/:actionId/status` | 按受限状态图推进动作；不能跳过授权或重写终态 |
| `GET /runs/:runId/artifacts` | 查询 run 的本地/远程产物引用 |
| `POST /actions/:actionId/artifacts` | 登记受控根内的产物路径、大小、SHA-256 和来源 |
| `GET /runs/:runId/evidence-checks` | 查询结构化 validator 结果 |
| `POST /actions/:actionId/evidence-checks` | 登记 pass/warn/fail 证据检查，绑定 action、step 和可选 artifact |
| `GET/POST /policies` | 查询或创建版本化 policy |
| `POST /policies/:policyId/activate` | 校验上层边界后激活 |
| `GET /reviews` | 按 `runId/projectId/taskId/status` 查询待沟通事项及决定 |
| `GET /evidence-library` | 按项目、任务、位置、校验状态和关键词聚合 artifact/evidence 证据索引 |
| `POST /runs/:runId/reviews` | Agent 创建评价请求；可传 `idempotencyKey` 防止重试生成重复请求 |
| `POST /reviews/:requestId/decisions` | 研究者批准、驳回、要求补充或终止 |

事件类别为 `fact | inference | decision | conclusion`；通用事件 API 拒绝追加 `conclusion`。专用 conclusion/promotion 接口都要求 `source=codex_conversation`、当前 context、无 open review 和精确 artifact 哈希。事件 API 不提供更新或删除。

action 状态图为 `proposed → authorized → executing`，执行后只能进入 `waiting_remote | waiting_user | succeeded | failed | cancelled` 允许的边；终态不可重写。授权请求必须声明 `source=codex_conversation`，保存的是决定摘要、哈希和可选 conversation reference，不保存完整聊天。方案、合同、任务工作流或 policy 与采用 context 任一发生 drift 时，创建和授权 action 都返回 `409 CONTEXT_DRIFT`。

可执行 capability 为 `local.process`、`remote.inspect`、`remote.task-root.create`、`files.upload`、`files.download`、`job.submit` 和 `job.cancel`。具体材料、Task、workflow step、脚本路径与科学参数由 Codex 根据当前研究上下文写入每次 spec，执行器、路由和 CLI 不注册材料专用路线。`remote.task-root.create` 只能创建或核对连接元数据和 policy 同时登记的 Task 写根；读取/下载受用户只读根约束，上传和作业受 Task 写根约束。`local.process` 使用可配置 executable allowlist 且 `shell=false`；`job.submit` 的 `method`、`softwareStack`、脚本和 LSF 资源全部进入 manifest，并同时受 task policy 与采用合同约束。完整 required/optional spec 字段以 `GET /execution-contract` 为准。

Agent 执行和评价相关 Web 页面只调用本节 GET 接口。上述 POST 接口是 `workbench-agent` skill/CLI 的机器入口，不是浏览器按钮入口。项目级超算元数据由 `workbench hpc show/configure` 统一读取和登记，CLI 内部复用项目 API 的相同校验，不保存 SSH 凭据。`GET /api/experiences` 支持 `projectId/taskId/search`；`POST /api/experiences/codex-capture` 由 CLI 幂等写入候选经验，自动关联 run 的项目/任务/核心步骤。Experience 的 `GET /api/experiences/:id/provenance` 返回 promotion 来源；promoted 条目的普通 PUT/DELETE 返回 409。

## 11. 受控远程操作

Base path：`/api/agent/v1/remote`。

| POST 路径 | 作用 |
|---|---|
| `/jobs/:jobId/status` | 通过 `bjobs`/`bhist` 查询记录作业 |
| `/jobs/:jobId/logs` | 通过 `bpeek` 读取日志 |
| `/jobs/:jobId/reconcile` | 服务重启或提交响应不确定后对账 |

inspect、传输、提交和取消不再提供 task/job 级直通写入口，统一通过上一节的 `executable-actions → authorize → execute`。远程执行同时要求 `WORKBENCH_REMOTE_ENABLED=1`、active task policy 以及批准的 host/root/operation；LSF 提交另要求 `WORKBENCH_ALLOW_REMOTE_LSF=1`。Workbench 不自动接受 host key。

## 通用约定

### 请求头
所有 POST/PUT 请求需携带 `Content-Type: application/json`。

### 响应格式
- 成功：返回对应资源对象或数组，HTTP 2xx
- 失败：`{"error": "错误描述", "code": "STABLE_CODE", "details": {}}`，后两项按需返回

### 时间格式
所有时间字段使用 ISO 8601 格式（UTC），如 `2026-07-09T12:16:07.824Z`。

### ID 格式
`{前缀}-{Unix毫秒时间戳}-{6位随机字符}`，如 `proj-1783599367824-r6jap2`。

### 级联删除规则
| 删除操作 | 级联删除 |
|---------|---------|
| 删除 Project | 无运行引用时级联；有运行引用时 409，只能归档 |
| 删除 Task | 无运行引用时级联；有运行引用时 409，只能归档 |
| 删除 StepProgress | → 关联的 StepFiles |
| 删除 StepFile | 无级联（仅删除自身） |
| 删除 Experience | 无级联 |
| 删除 ResearchPlan | 有运行引用时 409，只能归档 |

### 路径安全
文件仓库接口使用规范路径包含关系，拒绝绝对路径、`..`、同名前缀盘符逃逸，并检查现有目标或最近现有父目录的真实路径。Agent 文件传输进一步限制在稳定 Task 根内。服务仍按 V1 可信本机用户威胁模型运行，不支持局域网暴露或账号登录。
