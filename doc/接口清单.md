# DFT+DMFT Workbench 接口清单

> 最后更新：2026-07-19
> Base URL: `http://localhost:3001/api`
> 所有请求/响应均为 JSON 格式

---

## 1. 工作流模板

### GET /api/workflows
获取所有工作流模板列表。

**响应** `200 OK`
```json
[
  {
    "id": "dft-dmft-oneshot",
    "name": "One-shot DFT+DMFT",
    "description": "单次 DMFT 计算，不自洽更新电荷密度"
  }
]
```

> 注：`GET /api/workflows/all/full` 与 `GET /api/workflows/:id` 返回数据库中的完整模板；内置默认用于首次播种、缺失科学契约补充和显式重置。

## 2. 项目管理

### GET /api/projects
获取所有项目列表。

**响应** `200 OK`
```json
[
  {
    "id": "proj-1783599367824-r6jap2",
    "name": "V2O3 电子结构研究",
    "description": "研究 V2O3 的电子关联性质",
    "material": "V2O3",
    "working_dir": "D:/projects/v2o3",
    "created_at": "2026-07-09T12:16:07.824Z",
    "updated_at": "2026-07-09T12:16:07.824Z"
  }
]
```

### GET /api/projects/:id
获取单个项目详情（含任务数）。

**路径参数**

| 参数 | 类型 | 说明 |
|------|------|------|
| `id` | string | 项目 ID |

**响应** `200 OK`
```json
{
  "id": "proj-...",
  "name": "V2O3 电子结构研究",
  "description": "...",
  "material": "V2O3",
  "working_dir": "D:/projects/v2o3",
  "created_at": "...",
  "updated_at": "...",
  "task_count": 3
}
```
**错误** `404` — `{"error": "Project not found"}`

### POST /api/projects
创建项目。

**请求体**
```json
{
  "name": "V2O3 电子结构研究",      // 必填
  "description": "研究 V2O3...",    // 可选
  "material": "V2O3",              // 可选
  "working_dir": "D:/projects/v2o3" // 可选
}
```

**响应** `201 Created` — 返回完整项目对象
**错误** `400` — `{"error": "Name is required"}`

### PUT /api/projects/:id
更新项目（部分更新，未传字段保持不变）。

**请求体**（所有字段可选）
```json
{
  "name": "新名称",
  "description": "新描述",
  "material": "新材料",
  "working_dir": "D:/new/path"
}
```

**响应** `200 OK` — 返回更新后的项目对象
**错误** `404` — `{"error": "Project not found"}`

### DELETE /api/projects/:id
删除项目（级联删除其下所有任务、进度、文件关联）。

**响应** `200 OK` — `{"success": true}`
**错误** `404` — `{"error": "Project not found"}`

## 4. 步骤进度

### GET /api/tasks/:taskId/progress
获取任务的所有步骤进度（含关联文件）。

**响应** `200 OK`
```json
[
  {
    "id": "sp-...",
    "task_id": "task-...",
    "step_id": "dft-02",
    "status": "completed",
    "notes": "SCF 收敛到 10^-8",
    "updated_at": "...",
    "files": [
      {
        "id": "sf-...",
        "step_progress_id": "sp-...",
        "file_path": "D:/projects/v2o3/dft/scf.in",
        "file_name": "scf.in",
        "description": "SCF 输入文件",
        "is_remote": 0,
        "created_at": "..."
      }
    ]
  }
]
```

> 注：只返回有记录的步骤。未操作过的步骤不会出现在列表中，前端视为 `pending`。

### PUT /api/tasks/:taskId/progress/:stepId
更新（或创建）步骤的进度。Upsert 语义。

**路径参数**

| 参数 | 类型 | 说明 |
|------|------|------|
| `taskId` | string | 任务 ID |
| `stepId` | string | 步骤 ID（如 `dft-02`） |

**请求体**（所有字段可选，COALESCE 更新）
```json
{
  "status": "completed",    // pending | in_progress | completed | skipped
  "notes": "SCF 收敛了"     // 步骤笔记
}
```

**响应** `200 OK` — 返回更新后的 step_progress 对象

## 5. 步骤文件关联

### GET /api/tasks/:taskId/progress/:stepId/files
获取某步骤关联的文件列表。

**响应** `200 OK`
```json
[
  {
    "id": "sf-...",
    "step_progress_id": "sp-...",
    "file_path": "D:/projects/v2o3/dft/scf.in",
    "file_name": "scf.in",
    "description": "SCF 输入文件",
    "is_remote": 0,
    "created_at": "..."
  }
]
```

> 注：如果该步骤还没有 step_progress 记录，返回空数组 `[]`。

### POST /api/tasks/:taskId/progress/:stepId/files
为步骤添加文件关联。如果步骤还没有 step_progress 记录，会自动创建。

**请求体**
```json
{
  "file_path": "D:/projects/v2o3/dft/scf.in",  // 必填
  "file_name": "scf.in",                        // 必填
  "description": "SCF 输入文件",                 // 可选
  "is_remote": false                             // 可选，默认 false
}
```

**响应** `201 Created` — 返回创建的 step_files 对象
**错误** `400` — `{"error": "file_path and file_name are required"}`

### DELETE /api/step-files/:fileId
删除一个文件关联（仅删除关联记录，不删除实际文件）。

**路径参数**

| 参数 | 类型 | 说明 |
|------|------|------|
| `fileId` | string | step_files ID |

**响应** `200 OK` — `{"success": true}`
**错误** `404` — `{"error": "File not found"}`

## 6. 文件仓库（文件系统操作）

### GET /api/projects/:projectId/files?path=
浏览项目工作目录下的文件和子目录。

**查询参数**

| 参数 | 类型 | 说明 |
|------|------|------|
| `path` | string | 子目录相对路径（相对于 working_dir），可选，默认为根目录 |

**响应** `200 OK`
```json
{
  "entries": [
    {
      "name": "dft",
      "isDirectory": true,
      "size": 0,
      "modified": "2026-07-09T12:00:00.000Z",
      "relativePath": "dft"
    },
    {
      "name": "scf.in",
      "isDirectory": false,
      "size": 2048,
      "modified": "2026-07-09T12:30:00.000Z",
      "relativePath": "scf.in"
    }
  ],
  "currentPath": "",
  "exists": true
}
```

> 目录排在文件前面，按名称排序。

**错误**
- `400` — `{"error": "Project has no working directory set"}`
- `403` — `{"error": "Access denied: path outside working directory"}`（路径安全检查）
- `500` — `{"error": "Failed to read directory: ..."}`

### POST /api/projects/:projectId/files/mkdir
在项目工作目录下创建子目录（支持递归创建）。

**请求体**
```json
{
  "path": "dft",          // 父目录相对路径，可选，默认根目录
  "name": "scf_output"    // 新目录名，必填
}
```

**响应** `201 Created`
```json
{
  "success": true,
  "path": "dft/scf_output"
}
```

### GET /api/projects/:projectId/files/read?path=
读取文本文件内容（限 1MB 以内）。

**查询参数**

| 参数 | 类型 | 说明 |
|------|------|------|
| `path` | string | 文件相对路径（相对于 working_dir），必填 |

**响应** `200 OK`
```json
{
  "content": "&control\n  prefix='v2o3'\n  ...",
  "name": "scf.in",
  "size": 2048
}
```

**错误**
- `400` — `{"error": "Path is a directory"}` 或 `{"error": "File too large (max 1MB)"}`
- `403` — `{"error": "Access denied"}`
- `500` — `{"error": "Failed to read file: ..."}`

## 8. Task Spec、审批与执行审计

### GET/POST /api/tasks/:taskId/task-specs

列出任务计划，或创建 `draft` 计划。创建时服务端从步骤模板补充远端阶段目录、工作流依赖、输入输出、科学检查、成功判据、失败处理和审批点。

```json
{
  "step_id": "dft-02",
  "title": "运行 SCF",
  "command": "pw.x < scf.in > scf.out",
  "execution_payload": "",
  "timeout_seconds": 30
}
```

LSF 提交应把完整脚本放入 `execution_payload`。该字段与命令、目录、依赖和科学契约一起进入风险检查、审批哈希和 command run 快照；只提供 `bsub < file.lsf` 不能代表脚本内容已经被审批。

### PUT /api/task-specs/:specId

修改计划。任何修改都会使旧审批失效并把状态重置为 `draft`；executing、verifying 和 completed 计划不可修改。旧 approval/run 记录仍保留。

### POST /api/task-specs/:specId/check

验证 Task Spec 依赖、工作流步骤依赖和命令策略，计算完整内容哈希。依赖未完成返回 `409`；禁止命令进入 `blocked`；存在远端变更风险或科学审批点时进入 `awaiting_approval`，否则进入 `ready`。

### POST /api/task-specs/:specId/approvals

```json
{ "decision": "approved", "actor": "user", "note": "输入、目录和科学审批点已确认" }
```

审批绑定当前 `command_hash`，不会立即执行命令。

### POST /api/task-specs/:specId/runs

仅为 `ready` 且哈希/审批仍有效的计划创建一次 executing run。发送前保存完整 Task Spec 快照。

### PUT /api/task-specs/runs/:runId

```json
{
  "status": "completed",
  "exit_code": 0,
  "output_summary": "bounded terminal output",
  "evidence": [{ "kind": "terminal-output", "summary": "...", "source": "HPCPlus Edge PWA accessibility tree" }]
}
```

技术执行成功进入 `verifying`；远端失败进入 `failed`；超时、标记缺失或发送后失联进入 `unknown`。服务端和桥接器都不自动重试。

### POST /api/task-specs/:specId/verify

研究者根据科学检查项和证据把 verifying 计划标记为 `completed`、`failed` 或 `blocked`。所有决定必须填写人工结论；标记为 `completed` 时还必须提交至少一条结构化验证证据。退出码 0 本身不是科学成功。

## 9. LSF 作业状态与有界日志

### GET /api/scheduler-jobs/:jobRecordId

返回 LSF job ID、当前状态、上下次允许查询时间、全部 poll events 和 bounded log events。

### POST /api/scheduler-jobs/:jobRecordId/polls

在网页终端访问前创建 executing poll event，并返回服务端固定生成的 `bjobs -noheader -o stat <job_id>` 以及来源 Task Spec 的 `remote_workdir`；桥接器必须在该目录内执行查询。已有查询在执行时返回 `409`；距上次尝试不足 60 秒返回 `429`。

### PUT /api/scheduler-jobs/polls/:pollId

写入桥接状态、远端退出码、LSF 状态和有界摘要。`DONE` → verifying，`EXIT/ZOMBI` → failed，未知或桥接失败 → unknown，其他有效状态继续 monitoring。

### POST /api/scheduler-jobs/:jobRecordId/log-reads

```json
{ "relative_path": "dmft.out", "lines": 80 }
```

路径必须位于 Task Spec 目录内且不能包含绝对路径、`..`、通配符或控制字符；`lines` 范围为 1–200。服务端在发送前创建事件和独立 60 秒窗口，审计记录保存完整 `cd + tail` 命令，同时向桥接器分别返回 `remote_workdir` 与不含目录切换的固定 `bridge_command`。

### PUT /api/scheduler-jobs/log-reads/:logReadId

记录 completed/failed/unknown、远端退出码与最多 200 行的摘要。失败不会自动重发，也不会自动修改科学参数。

## 通用约定

### 请求头
所有 POST/PUT 请求需携带 `Content-Type: application/json`。

### 响应格式
- 成功：返回对应资源对象或数组，HTTP 2xx
- 失败：`{"error": "错误描述"}`，HTTP 4xx/5xx

### 时间格式
所有时间字段使用 ISO 8601 格式（UTC），如 `2026-07-09T12:16:07.824Z`。

### ID 格式
`{前缀}-{Unix毫秒时间戳}-{6位随机字符}`，如 `proj-1783599367824-r6jap2`。

### 级联删除规则
| 删除操作 | 级联删除 |
|---------|---------|
| 删除 Project | → 该项目下所有 Tasks → 每个 Task 的 StepProgress → 每条 StepProgress 的 StepFiles |
| 删除 Task | → 该任务下所有 StepProgress/StepFiles 与 TaskSpecs/ApprovalEvents/CommandRuns |
| 删除 StepProgress | → 关联的 StepFiles |
| 删除 StepFile | 无级联（仅删除自身） |
| 删除 Experience | 无级联 |

### 路径安全
文件仓库接口（`/files`、`/files/mkdir`、`/files/read`）会检查请求路径是否在项目 `working_dir` 范围内，防止目录穿越攻击。
