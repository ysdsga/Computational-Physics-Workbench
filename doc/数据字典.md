# 数据字典（schema v5）

数据库为 SQLite，默认路径 `data/workbench.db`，启用 WAL 与外键。测试通过 `WORKBENCH_DB_PATH` 注入临时库。

## 核心业务表

| 表 | 作用 | 主要关系 |
|---|---|---|
| `projects` | 材料/研究体系与本地 `working_dir`、HPC JSON | 根实体 |
| `tasks` | 复杂研究任务、稳定 Task 根、独立 Workflow 快照 | → Project |
| `workflow_templates` | 可编辑 Workflow 模板 | 创建 Task 时复制 |
| `step_progress` | 核心 step 状态、笔记、命令/LSF 模板 | → Task |
| `step_files` | step 关联文件路径引用 | → StepProgress |
| `research_plans` | Project 工作目录中 Markdown 的可检索元数据 | → Project |
| `experiences` | 人工/候选/确认经验与适用边界 | 可关联 Project/Task/Run/Artifact |

## 研究运行表

| 表 | 作用 |
|---|---|
| `research_runs` | Run 身份及 Task Spec：Confirmed Envelope + Working Plan |
| `run_events` | 追加式 fact/inference/decision/conclusion 时间线 |
| `run_actions` | Stage 下 Codex 动作及不可变 spec hash |
| `remote_jobs` | originating Action 对应的远程调度器作业 |
| `run_artifacts` | 本地/远程文件证据、哈希与有效性 |
| `evidence_checks` | validator 对 Artifact/Action 的结构化检查 |
| `pending_items` | 面向 Codex 或 Researcher 的统一注意事项 |

## tasks

关键字段：

- `workflow_id`：来源模板 ID。
- `workflow_snapshot`：该 Task 独立使用的完整 JSON。
- `task_root_rel`：Project 工作目录下稳定根；只创建这一层，不创建 Stage 子目录。
- `status`：`active | paused | completed | archived`。

## research_runs

| 字段 | 含义 |
|---|---|
| `task_id`, `research_plan_id` | Task 与 Research Plan |
| `status` | `draft | active | waiting_researcher | completed | terminated` |
| `objective` | Task Spec objective |
| `confirmed_envelope_json` | 规范化 Confirmed Envelope |
| `working_plan_json` | Codex 可变 Working Plan |
| `envelope_revision` | 首次确认为 1；每次材料性修订递增 |
| `envelope_confirmed_at` | 最近确认时间 |
| `envelope_confirmation_summary` | 决定摘要，不保存完整聊天 |
| `current_stage_id` | Working Plan 当前核心 Stage |
| `idempotency_key` | Task 内创建幂等身份 |

部分唯一索引保证每个 Task 只有一个 `draft | active | waiting_researcher` Run。API 序列化时额外返回 `confirmed_envelope_sha256` 和 `working_plan_sha256`，它们由规范化 JSON 计算，不另存列。

Confirmed Envelope schema v1：

```json
{
  "schemaVersion": 1,
  "coreStageIds": ["stage-id"],
  "scientificCommitments": ["..."],
  "allowedCapabilities": ["local.process"],
  "allowedMethods": ["..."],
  "allowedSoftwareStacks": ["..."],
  "hpcProfileId": null,
  "resourceLimits": {
    "maxCoresPerJob": 1,
    "maxWallMinutes": 10,
    "maxConcurrentJobs": 1,
    "maxAutomaticRetries": 1
  },
  "protectedRelativePaths": [],
  "completionEvidence": ["..."],
  "researcherGates": [],
  "autonomy": {
    "allowWorkingPlanEdits": true,
    "allowRetriesWithinLimits": true,
    "allowOwnJobCancellation": true
  }
}
```

## run_events

`sequence` 在 Run 内递增；`category` 为 `fact | inference | decision | conclusion`，`actor_type` 为 `agent | researcher | system`。可选 `idempotency_key` 在 Run 内唯一。`conclusion` 只有 `actor_type=researcher` 且 `source=codex_conversation` 才能写入。没有更新/删除接口。

## run_actions

| 字段 | 含义 |
|---|---|
| `stage_id` | 必须属于 Envelope 与当前 Task Workflow |
| `step_id` | 可选核心 step |
| `parent_action_id` | 可选 Action 分解关系 |
| `action_type` | 通用 capability 或 Codex 记录动作类型 |
| `status` | `ready | executing | waiting_remote | waiting_codex | waiting_researcher | succeeded | failed | cancelled` |
| `spec_json`, `spec_sha256` | 不可变 Action 规格和哈希 |
| `executor` | 固定 `codex` |
| `idempotency_key` | Run 内唯一 |
| `result_json`, `error_json` | 结构化结果/错误 |

确认 Envelope 后 Action 直接创建为 `ready`，不再有 `proposed/authorized` 或授权摘要字段。

## remote_jobs

每行必须绑定 `run_id + action_id + stage_id`。同一 Action 可以有多个不同 `idempotency_key` 的 Job。

主要字段：`action_token`、`profile_id`、`host`、`remote_workdir`、`scheduler`、`job_id`、`job_name`、`status`、`submission_spec_json`、`script_sha256`、`resources_json`、`last_observation_json`、提交 stdout/stderr 与时间。

提交前插入 `prepared`；不确定响应为 `submission_uncertain`。`(host, scheduler, job_id)` 在 job ID 非空时唯一。

## run_artifacts / evidence_checks

Artifact 必须绑定 Action 与 Stage：

- `location`：`local | remote`。
- `path`：Task 相对路径或远程引用。
- `size_bytes`, `sha256`：内容身份。
- `category`：receipt、downloaded-evidence、scientific-output 等。
- `validity`：`valid | suspect | invalid | superseded`。
- `superseded_by_id`：替代 Artifact。
- `remote_job_id`：远程 Artifact 必须绑定同一 Action 的已记录 Job。

EvidenceCheck 保存 validator name/version、`pass | warn | fail` 与结构化 `result_json`。它不等同 researcher conclusion。

## pending_items

- `audience`：`codex | researcher`。
- `status`：`open | resolved | dismissed`。
- `stage_id`：可空；有值时只阻塞该 Stage。
- `action_id`, `remote_job_id`：可选定位。
- `detail_json.blocksRun`：`true` 时形成执行阻塞。
- researcher item 只接受 `source=codex_conversation` 的解决或 Envelope 修订。

## experiences

在原有标题、正文、标签和 Project/Task/step 关联上，v5 增加：

- `category`：经验类别。
- `status`：`manual | candidate | confirmed`。
- `applicable_scope`：适用条件与不可外推边界。
- `source_run_id`、`source_artifact_ids`：来源。
- `source_kind`：`researcher | codex | imported`。

Experience 与 Evidence 是不同对象；candidate 不是结论或证明。

## 迁移与备份

当前 `PRAGMA user_version=5`。迁移会依次保留早期备份，并在 v5 前创建 `*.before-essential-v3.db`。v4 旧运行控制表非空时拒绝迁移；空表可安全替换，业务数据保留。正式迁移后应核对表计数、外键、Task/Plan/Experience 内容与 Context。
