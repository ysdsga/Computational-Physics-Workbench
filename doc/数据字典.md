# DFT+DMFT Workbench 数据字典

> 最后核对：2026-07-21（新增 research_plans 表）
> 数据库：SQLite，文件路径 `data/workbench.db`
> 启用：WAL 模式 + 外键约束

---

## 表结构总览

| 表名 | 说明 | 关联 |
|------|------|------|
| `projects` | 项目（研究一个材料/体系） | — |
| `tasks` | 任务（一次具体计算运行） | → projects |
| `step_progress` | 步骤进度（工作流每步的状态/笔记） | → tasks |
| `step_files` | 步骤文件关联（文件引用记录） | → step_progress |
| `experiences` | 经验库条目 | → projects / tasks（可选软关联） |
| `workflow_templates` | 可编辑工作流模板 | — |
| `research_plans` | 研究方案（与 AI 讨论沉淀） | → projects（可选软关联） |

---

## 1. projects（项目表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | TEXT | PRIMARY KEY | 项目 ID，格式 `proj-{timestamp}-{random6}` |
| `name` | TEXT | NOT NULL | 项目名称，如 "V₂O₃ 电子结构研究" |
| `description` | TEXT | DEFAULT '' | 项目描述 |
| `material` | TEXT | DEFAULT '' | 材料/体系名称，如 "V2O3" |
| `working_dir` | TEXT | DEFAULT '' | 文件仓库工作目录绝对路径，如 `D:/projects/v2o3` |
| `hpc_config` | TEXT | NULL | HPC 配置 JSON；用于生成复制粘贴式 LSF/scp 命令 |
| `created_at` | TEXT | NOT NULL | 创建时间（ISO 8601） |
| `updated_at` | TEXT | NOT NULL | 更新时间（ISO 8601） |

**索引**：无（全表扫描，数据量小）
**级联**：删除 project 时级联删除其下所有 tasks（→ step_progress → step_files）

---

## 2. tasks（任务表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | TEXT | PRIMARY KEY | 任务 ID，格式 `task-{timestamp}-{random6}` |
| `project_id` | TEXT | NOT NULL, FK → projects(id) | 所属项目 ID |
| `name` | TEXT | NOT NULL | 任务名称，如 "V₂O₃ 顺磁性 one-shot DMFT" |
| `description` | TEXT | DEFAULT '' | 任务描述 |
| `workflow_id` | TEXT | NOT NULL | 创建任务时使用的来源模板 ID，如 `dft-dmft-oneshot` |
| `workflow_snapshot` | TEXT | 可空（兼容旧数据） | 任务自己的完整工作流 JSON；新任务创建时复制模板，旧任务首次迁移时从当前模板补齐 |
| `status` | TEXT | DEFAULT 'active' | 任务状态（见下表） |
| `created_at` | TEXT | NOT NULL | 创建时间 |
| `updated_at` | TEXT | NOT NULL | 更新时间 |

**status 枚举值**：

| 值 | 含义 | 颜色 |
|----|------|------|
| `active` | 进行中 | 绿色 #22c55e |
| `paused` | 已暂停 | 橙色 #f59e0b |
| `completed` | 已完成 | 蓝色 #3b82f6 |
| `archived` | 已归档 | 灰色 #6b6b80 |

**级联**：删除 task 时级联删除其下所有 step_progress（→ step_files）

---

## 3. step_progress（步骤进度表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | TEXT | PRIMARY KEY | 进度记录 ID，格式 `sp-{timestamp}-{random6}` |
| `task_id` | TEXT | NOT NULL, FK → tasks(id) | 所属任务 ID |
| `step_id` | TEXT | NOT NULL | 步骤 ID（来自工作流模板，如 `dft-02`、`wan-03`） |
| `status` | TEXT | DEFAULT 'pending' | 步骤状态（见下表） |
| `notes` | TEXT | DEFAULT '' | 步骤笔记 |
| `commands` | TEXT | NULL | 用户自定义命令的 JSON 数组；为空时使用模板命令 |
| `lsf_script` | TEXT | NULL | 用户自定义 LSF 脚本；为空时使用模板脚本 |
| `updated_at` | TEXT | NOT NULL | 更新时间 |

**唯一约束**：`UNIQUE(task_id, step_id)` — 一个任务的一个步骤只有一条进度记录

**status 枚举值**：

| 值 | 含义 | 流程图颜色 |
|----|------|-----------|
| `pending` | 待开始 | 灰色 |
| `in_progress` | 进行中 | 蓝色 |
| `completed` | 已完成 | 绿色 |
| `skipped` | 已跳过 | 灰色（半透明） |

**说明**：step_progress 是「按需创建」的——只有当用户首次操作某步骤时（设置状态或添加笔记），才会插入一条记录。未操作过的步骤默认为 `pending`，前端通过 `progressMap[stepId]` 查找，找不到即视为 pending。

**级联**：删除 step_progress 时级联删除其下所有 step_files

---

## 4. step_files（步骤文件关联表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | TEXT | PRIMARY KEY | 文件关联 ID，格式 `sf-{timestamp}-{random6}` |
| `step_progress_id` | TEXT | NOT NULL, FK → step_progress(id) | 所属步骤进度 ID |
| `file_path` | TEXT | NOT NULL | 文件完整路径，如 `D:/projects/v2o3/dft/scf.in` |
| `file_name` | TEXT | NOT NULL | 文件名，如 `scf.in` |
| `description` | TEXT | DEFAULT '' | 文件描述 |
| `is_remote` | INTEGER | DEFAULT 0 | 兼容旧数据的遗留字段；现役 UI 不再创建远程文件引用 |
| `created_at` | TEXT | NOT NULL | 创建时间 |

**说明**：此表记录的是「文件路径引用」，不是文件内容本身。现役文件选择器只关联项目 `working_dir` 下的已有文件。

---

## 5. experiences（经验库表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | TEXT | PRIMARY KEY | 经验 ID，格式 `exp-{timestamp}-{random6}` |
| `title` | TEXT | NOT NULL | 标题 |
| `content` | TEXT | NOT NULL | 正文内容 |
| `tags` | TEXT | DEFAULT '[]' | 标签 JSON 数组字符串，如 `["V2O3","Wannier90"]` |
| `related_project_id` | TEXT | NULL | 关联项目 ID（可选） |
| `related_task_id` | TEXT | NULL | 关联任务 ID（可选） |
| `related_step_id` | TEXT | NULL | 关联步骤 ID（可选，如 `dft-02`） |
| `created_at` | TEXT | NOT NULL | 创建时间 |
| `updated_at` | TEXT | NOT NULL | 更新时间 |

**说明**：`tags` 字段存储为 JSON 字符串（SQLite 不支持原生数组），前端读取时 `JSON.parse()`，写入时 `JSON.stringify()`。三个关联字段都是软关联（无外键约束），允许为 NULL。

## 6. workflow_templates（工作流模板表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | TEXT | PRIMARY KEY | 模板 ID，如 `dft-dmft-oneshot` |
| `name` | TEXT | NOT NULL | 模板名称 |
| `description` | TEXT | DEFAULT '' | 模板说明 |
| `data` | TEXT | NOT NULL, DEFAULT '{}' | `{ stages, steps }` 的 JSON 文档 |
| `updated_at` | TEXT | NOT NULL | 最近更新时间 |

后端从 `src/data/workflows.ts` 增量播种缺失的内置模板，不覆盖已有同 ID 记录，因此用户编辑可以保留；"重置为默认"会用源码中的同 ID 内置模板覆盖数据库记录。

---

## 7. research_plans（研究方案表 · v3 项目目录文件型）

> **v3 (2026-08-09)**：方案正文不入库，文件保存在所属项目 `working_dir`，本表只存轻量元数据。初始化不再删除重建该表。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | TEXT | PRIMARY KEY | 方案 ID，格式 `rp-{timestamp}-{random6}` |
| `file_name` | TEXT | NOT NULL | 项目 `working_dir` 下的文件名，如 `v2o3_plan.md`；与 `project_id` 组合唯一 |
| `title` | TEXT | NOT NULL | 显示标题（默认=文件名去掉 `.md`，可手改） |
| `project_id` | TEXT | NULL | 所属项目 ID；API 强制必填，数据库保留 NULL 兼容旧记录 |
| `linked_task_ids` | TEXT | DEFAULT '[]' | 关联任务 ID 的 JSON 数组（软关联） |
| `status` | TEXT | DEFAULT 'draft' | 状态（见下表） |
| `tags` | TEXT | DEFAULT '[]' | 标签 JSON 数组字符串 |
| `created_at` | TEXT | NOT NULL | 创建时间 |
| `updated_at` | TEXT | NOT NULL | 更新时间（正文保存时也会刷新） |

**status 枚举值**：

| 值 | 含义 | 颜色 |
|----|------|------|
| `draft` | 草稿 | 灰色 #6b6b80 |
| `active` | 进行中 | 绿色 #22c55e |
| `completed` | 已完成 | 蓝色 #3b82f6 |
| `archived` | 已归档 | 橙色 #f59e0b |

**说明**：
- 正文唯一源 = `<project.working_dir>/<file_name>` 真实 Markdown 文件。
- 不再创建或扫描工作台根目录的 `research-plans/`。
- `GET /api/research-plans` 时扫描有效项目目录，对 DB 中无记录的 `*.md` 自动补元数据。
- `project_id` 与 `linked_task_ids` 仍为软关联，无外键约束；新建和导入必须提供有效 `project_id`。
- 文件丢失但 DB 记录还在时，列表返回 `missing: true`，前端给出警告。

## 实体关系图 (ER Diagram)

```
projects (id, working_dir, hpc_config)
  1 ── N tasks (id, project_id, workflow_id, workflow_snapshot)
           1 ── N step_progress (id, task_id, step_id, commands, lsf_script)
                     1 ── N step_files (id, step_progress_id, file_path)

workflow_templates (id, data JSON)
  1 ── N tasks.workflow_id  [仅记录创建来源，无数据库外键]

experiences
  └── related_project_id / related_task_id / related_step_id  [可选软关联]

research_plans (id, file_name, project_id, linked_task_ids)
  ├── file_name             → projects.working_dir/*.md（文件系统，正文唯一源）
  ├── project_id            [所属项目，API 必填]
  └── linked_task_ids       [JSON 数组，软关联到 tasks]
```

## 工作流模板数据

现役模板存储在 `workflow_templates` 表中。创建任务时会把选中的模板完整复制到 `tasks.workflow_snapshot`，之后任务运行和编辑均以该副本为准；修改模板不会改变已有任务。`workflow_id` 只保留来源关系。`src/data/workflows.ts` 只承担内置默认值、首次播种和重置回退，不是运行期唯一数据源。

### 工作流：One-shot DFT+DMFT (`dft-dmft-oneshot`)

| 阶段 | ID | 步骤数 | 颜色 |
|------|----|--------|------|
| 准备阶段 | `prep` | 6 步 | 蓝色 #3b82f6 |
| DFT 计算 | `dft` | 4 步（2 可选） | 绿色 #22c55e |
| Wannier90 计算 | `wannier` | 5 步 | 橙色 #f59e0b |
| DMFT 计算 | `dmft` | 3 步 | 紫色 #8b5cf6 |
| 结果检查 | `check` | 2 步 | 红色 #ef4444 |

合计 20 个步骤，其中 DFT 阶段有 2 个可选步骤。

**步骤 ID 规范**：`{阶段缩写}-{两位序号}`，如 `prep-01`、`dft-02`、`wan-03`、`dmft-01`、`chk-02`

## ID 生成规则

所有表的主键均在应用层生成（非数据库自增），格式为：

```
{表前缀}-{Unix毫秒时间戳}-{6位随机字母数字}
```

| 表 | 前缀 | 示例 |
|----|------|------|
| projects | `proj` | `proj-1783599367824-r6jap2` |
| tasks | `task` | `task-1783600861420-7716an` |
| step_progress | `sp` | `sp-1783600867160-uqwtxj` |
| step_files | `sf` | `sf-1783600870000-abc123` |
| experiences | `exp` | `exp-1783600880000-xyz789` |
| research_plans | `rp` | `rp-1784619824239-owrocf` |
