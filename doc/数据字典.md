# DFT+DMFT Workbench 数据字典

> 最后更新：2026-07-19
> 数据库：SQLite，文件路径 `data/workbench.db`
> 启用：WAL 模式 + 外键约束

---

## 表结构总览

| 表名 | 说明 | 关联 |
|------|------|------|
| `projects` | 项目（研究一个材料/体系） | — |
| `tasks` | 任务（一次具体计算运行） | → projects |
| `step_progress` | 步骤进度（工作流每步的状态/笔记） | → tasks |
| `step_files` | 步骤文件关联（文件引用记录） | → step_progress |
| `experiences` | 经验库条目 | → projects / tasks（可选软关联） |
| `workflow_templates` | 可编辑工作流模板 | — |
| `schema_migrations` | 兼容迁移版本 | — |
| `task_specs` | 可审计执行计划与科学契约 | → tasks |
| `approval_events` | 不可变审批事件 | → task_specs |
| `command_runs` | 单次执行、结果证据和计划快照 | → task_specs |
| `scheduler_jobs` | 已接受的 LSF 作业与节流状态 | → task_specs |
| `scheduler_poll_events` | 不可变状态查询审计 | → scheduler_jobs |
| `scheduler_log_events` | 不可变有界日志读取审计 | → scheduler_jobs |

## 1. projects（项目表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | TEXT | PRIMARY KEY | 项目 ID，格式 `proj-{timestamp}-{random6}` |
| `name` | TEXT | NOT NULL | 项目名称，如 "V₂O₃ 电子结构研究" |
| `description` | TEXT | DEFAULT '' | 项目描述 |
| `material` | TEXT | DEFAULT '' | 材料/体系名称，如 "V2O3" |
| `working_dir` | TEXT | DEFAULT '' | 文件仓库工作目录绝对路径，如 `D:/projects/v2o3` |
| `created_at` | TEXT | NOT NULL | 创建时间（ISO 8601） |
| `updated_at` | TEXT | NOT NULL | 更新时间（ISO 8601） |

**索引**：无（全表扫描，数据量小）
**级联**：删除 project 时级联删除其下所有 tasks（→ step_progress → step_files）

## 2. tasks（任务表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | TEXT | PRIMARY KEY | 任务 ID，格式 `task-{timestamp}-{random6}` |
| `project_id` | TEXT | NOT NULL, FK → projects(id) | 所属项目 ID |
| `name` | TEXT | NOT NULL | 任务名称，如 "V₂O₃ 顺磁性 one-shot DMFT" |
| `description` | TEXT | DEFAULT '' | 任务描述 |
| `workflow_id` | TEXT | NOT NULL | 工作流模板 ID，如 `dft-dmft-oneshot` |
| `status` | TEXT | DEFAULT 'active' | 任务状态（见下表） |
| `folder_name` | TEXT | DEFAULT '' | 稳定的计算目录名；创建后不随任务显示名称修改 |
| `created_at` | TEXT | NOT NULL | 创建时间 |
| `updated_at` | TEXT | NOT NULL | 更新时间 |

**status 枚举值**：

| 值 | 含义 | 颜色 |
|----|------|------|
| `active` | 进行中 | 绿色 #22c55e |
| `paused` | 已暂停 | 橙色 #f59e0b |
| `completed` | 已完成 | 蓝色 #3b82f6 |
| `archived` | 已归档 | 灰色 #6b6b80 |

**级联**：删除 task 时级联删除其下所有 step_progress（→ step_files）

**目录稳定性**：文件浏览和 HPC 路径使用 `folder_name`，`name` 仅作为可修改的显示名称。旧数据迁移时以当时的任务名称补齐 `folder_name`。

## 3. step_progress（步骤进度表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | TEXT | PRIMARY KEY | 进度记录 ID，格式 `sp-{timestamp}-{random6}` |
| `task_id` | TEXT | NOT NULL, FK → tasks(id) | 所属任务 ID |
| `step_id` | TEXT | NOT NULL | 步骤 ID（来自工作流模板，如 `dft-02`、`wan-03`） |
| `status` | TEXT | DEFAULT 'pending' | 步骤状态（见下表） |
| `notes` | TEXT | DEFAULT '' | 步骤笔记 |
| `updated_at` | TEXT | NOT NULL | 更新时间 |

**唯一约束**：`UNIQUE(task_id, step_id)` — 一个任务的一个步骤只有一条进度记录

**status 枚举值**：

| 值 | 含义 | 流程图颜色 |
|----|------|-----------|
| `pending` | 待开始 | 灰色 |
| `in_progress` | 进行中 | 蓝色 |
| `completed` | 已完成 | 绿色 |
| `skipped` | 已跳过 | 灰色（半透明） |

**说明**：step_progress 是「按需创建」的——只有当用户首次操作某步骤时（设置状态或添加笔记），才会插入一条记录。未操作过的步骤默认为 `pending`，前端通过 `progressMap[stepId]` 查找，找不到即视为 pending。

**级联**：删除 step_progress 时级联删除其下所有 step_files

## 4. step_files（步骤文件关联表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | TEXT | PRIMARY KEY | 文件关联 ID，格式 `sf-{timestamp}-{random6}` |
| `step_progress_id` | TEXT | NOT NULL, FK → step_progress(id) | 所属步骤进度 ID |
| `file_path` | TEXT | NOT NULL | 文件完整路径，如 `D:/projects/v2o3/dft/scf.in` |
| `file_name` | TEXT | NOT NULL | 文件名，如 `scf.in` |
| `description` | TEXT | DEFAULT '' | 文件描述 |
| `is_remote` | INTEGER | DEFAULT 0 | 是否远程文件引用（0=本地，1=远程如 HPC 上的文件） |
| `created_at` | TEXT | NOT NULL | 创建时间 |

**说明**：此表记录的是「文件路径引用」，不是文件内容本身。文件实际存储在项目 `working_dir` 指定的目录或远程服务器上。`is_remote=1` 用于标记 HPC 等远程文件，前端显示不同图标。

## 5. experiences（经验库表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | TEXT | PRIMARY KEY | 经验 ID，格式 `exp-{timestamp}-{random6}` |
| `title` | TEXT | NOT NULL | 标题 |
| `content` | TEXT | NOT NULL | 正文内容 |
| `tags` | TEXT | DEFAULT '[]' | 标签 JSON 数组字符串，如 `["V2O3","Wannier90"]` |
| `related_project_id` | TEXT | NULL | 关联项目 ID（可选） |
| `related_task_id` | TEXT | NULL | 关联任务 ID（可选） |
| `related_step_id` | TEXT | NULL | 关联步骤 ID（可选，如 `dft-02`） |
| `source_task_spec_id` | TEXT | NULL, FK → task_specs(id), ON DELETE SET NULL | 人工沉淀经验的来源计划；版本 10 新增 |
| `created_at` | TEXT | NOT NULL | 创建时间 |
| `updated_at` | TEXT | NOT NULL | 更新时间 |

**说明**：`tags` 字段存储为 JSON 字符串。项目、任务和步骤关联保持软关联；当提供 `source_task_spec_id` 时，服务端从来源计划推导并校验三项关联，避免经验被链接到错误任务。删除来源计划只清空来源 ID，不删除研究经验。

## 6. workflow_templates 与 schema_migrations

`workflow_templates` 保存用户可编辑的 stages/steps JSON。内置默认位于 `src/data/workflows.ts`，首次播种和重置时使用；读取旧模板时，服务端只为缺失字段补充内置科学契约，不覆盖用户已经保存的值。

`schema_migrations` 记录已经应用的迁移版本。迁移必须可在旧数据库上重复安全启动；版本 5–7 引入 Task Spec、运行快照和结构化科学契约，版本 8–9 引入 LSF 监控与有界日志审计，版本 10 增加经验来源追踪。

## 7. task_specs（执行计划与科学契约）

| 字段组 | 字段 | 说明 |
|--------|------|------|
| 归属 | `id`, `task_id`, `step_id`, `title` | 计划及其任务/步骤 |
| 执行目标 | `remote_workdir`, `command`, `execution_payload`, `timeout_seconds` | 经审查的远端目录、单条命令、完整 LSF/执行载荷快照和超时 |
| 依赖 | `dependencies`, `step_dependencies` | Task Spec ID 与工作流步骤 ID 的 JSON 数组 |
| 科学契约 | `input_files`, `expected_outputs`, `preconditions`, `scientific_checks`, `success_criteria`, `approval_points`, `failure_handling` | 均为 JSON 字符串数组；不得由智能体填入未经确认的科学参数 |
| 风险/审批 | `risk_class`, `approval_required`, `command_hash` | 风险分类与覆盖完整计划内容的 SHA-256 |
| 状态 | `status`, `failure_policy` | draft → check/approval → ready → executing → verifying → completed；也可进入 failed/unknown/blocked |
| 时间 | `created_at`, `updated_at` | ISO 8601 时间 |

任何影响执行或验证语义的字段修改都会清空当前哈希并回到 `draft`。命令策略同时检查 `command` 与 `execution_payload`，因此脚本内部的写操作或禁止命令无法被 `bsub` 外壳隐藏；目录切换、显式绝对/home-relative 路径、`..` 越界、递归扫描、后台运行和间接 shell 执行也会被阻止。每次桥接执行都通过独立参数进入并核验 Task Spec 已审批目录，调度查询也继承原 Task Spec 的工作目录。`unknown` 表示远端状态无法确定，禁止自动重试。

服务启动时，任何仍为 `executing` 的 `command_runs`、`scheduler_poll_events` 和 `scheduler_log_events` 都属于上一次服务生命周期的中断记录。系统会以同一事务补齐 `finished_at` 和恢复原因：命令运行及调度查询会把关联 Task Spec 置为 `unknown`，调度查询还会把 job 状态置为 `UNKNOWN`；日志读取只结束该读取事件，不改变仍在监控的计算任务。重复恢复是幂等的。

## 8. approval_events（不可变审批事件）

| 字段 | 说明 |
|------|------|
| `task_spec_id` | 被审批的 Task Spec |
| `decision` | `approved` 或 `rejected` |
| `command_hash` | 审批时的完整内容哈希 |
| `actor`, `note`, `created_at` | 审批人、说明和时间 |

审批记录不提供更新或删除 API。旧审批保留用于审计，但只对完全一致的当前哈希有效。

## 9. command_runs（单次执行审计）

| 字段组 | 字段 | 说明 |
|--------|------|------|
| 标识 | `id`, `task_spec_id`, `attempt_no` | 同一计划的人工触发执行序号 |
| 执行 | `status`, `started_at`, `finished_at`, `exit_code` | 执行状态与远端退出码 |
| 证据 | `output_summary`, `evidence`, `error_message`, `verification_note` | 最多 65,536 字符的终端摘要、结构化证据和人工验证结论；科学验证通过必须有结论与证据 |
| 快照 | `command_hash`, `task_spec_snapshot` | 发送时的哈希和完整计划 JSON，后续修订不会改变旧运行语义 |

## 10. scheduler_jobs、scheduler_poll_events 与 scheduler_log_events

- `scheduler_jobs` 只在已审批的 LSF 提交成功解析出数字 job ID 后创建，保存 `SUBMITTED/PEND/RUN/DONE/EXIT/...`、上次查询时间和两个独立的下次允许时间。
- `scheduler_poll_events` 在网页终端访问前创建，命令固定为服务端生成的 `bjobs -noheader -o stat <job_id>`。开始时间一经写入即占用至少 60 秒窗口。
- `scheduler_log_events` 保存相对路径、1–200 行上限、服务端生成的 `cd -- <Task Spec cwd> && tail ...`、有界输出和桥接状态。执行时目录和 `tail` 命令分开传给桥接器，桥接器核对 `$PWD` 后才读取；绝对路径、`..`、通配符及控制字符在创建事件前被拒绝。
- `DONE` 将 Task Spec 转到 `verifying`，`EXIT/ZOMBI` 转到 `failed`，断线、超时、无法识别或 `UNKWN` 转到 `unknown`；所有 unknown 都停止自动动作。

## 工作流模板数据

内置默认定义在 `src/data/workflows.ts`，运行时模板保存在 `workflow_templates`。任务通过 `workflow_id` 引用模板；每个步骤还包含 `dependsOn`、`preconditions`、`scientificChecks`、`successCriteria`、`failureHandling` 和 `approvalPoints`。

### 工作流：One-shot DFT+DMFT (`dft-dmft-oneshot`)

| 阶段 | ID | 步骤数 | 颜色 |
|------|----|--------|------|
| 准备阶段 | `prep` | 6 步 | 蓝色 #3b82f6 |
| DFT 计算 | `dft` | 4 步（2 可选） | 绿色 #22c55e |
| Wannier90 计算 | `wannier` | 5 步 | 橙色 #f59e0b |
| DMFT 计算 | `dmft` | 3 步 | 紫色 #8b5cf6 |
| 结果检查 | `check` | 2 步 | 红色 #ef4444 |

**步骤 ID 规范**：`{阶段缩写}-{两位序号}`，如 `prep-01`、`dft-02`、`wan-03`、`dmft-01`、`chk-02`

## ID 生成规则

所有表的主键均在应用层生成（非数据库自增），格式为：

```
{表前缀}-{Unix毫秒时间戳}-{6位随机字母数字}
```

| 表 | 前缀 | 示例 |
|----|------|------|
| projects | `proj` | `proj-1783599367824-r6jap2` |
| tasks | `task` | `task-1783600861420-7716an` |
| step_progress | `sp` | `sp-1783600867160-uqwtxj` |
| step_files | `sf` | `sf-1783600870000-abc123` |
| experiences | `exp` | `exp-1783600880000-xyz789` |
