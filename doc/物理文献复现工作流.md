# 物理文献复现工作流

[English](PAPER_REPRODUCTION_WORKFLOW.en.md) | 中文

## 目标

“物理文献复现”是一套面向解析理论、模型数值和真实材料计算论文的通用核心工作流。它不把“程序成功退出”当作论文结论已复现，而是围绕四个对象组织全过程：

1. 论文中可定位的目标主张（claim）；
2. 能否进行公平比较的条件；
3. 从来源、参数、运行到裁决的证据链；
4. 研究者最终允许对外声称的结论。

论文专属模型、参数、容差、软件和运行矩阵写入 Research Plan 与 Working Plan，不固化在通用工作流模板中。

本指南对应稳定工作流 ID `physics-literature-reproduction`。当前[内置模板](../src/data/workflows.ts)包含 8 个阶段、27 个步骤，其中 3 个类型化规格步骤标记为可选。运行时模板以数据库为准，已创建任务使用各自的工作流快照；文档和内置默认值不会自动覆盖用户修改。英文界面只翻译仍与内置原文一致的显示字段，不改变 ID、任务快照、命令或研究者内容。

## 两个独立的复现维度

复现深度和独立性不能合并成一条等级轴。

复现深度可选择：

- 可运行性：验证作者产物或方法入口能否在记录环境中运行；
- 核心机制：重建决定结果的核心推导、算法或计算链；
- 关键主张：复现预先选定的公式、图、表、趋势、相边界或机制结论；
- 完整结果：复现论文约定范围内的完整结果集；
- 后续基线：在通过关键主张复现后，将产物冻结为新研究的比较基线。

独立性模式可选择：

- 原作者产物复跑：使用作者代码、数据或脚本；
- 独立重建：根据论文与方法资料重新推导或实现；
- 双路线交叉验证：同时保留复跑与独立重建，比较关键中间量。

例如，“关键主张 + 作者代码复跑”和“关键主张 + 独立重建”具有不同证据强度，不能互相替代。

## 八阶段核心骨架

| 阶段（稳定 ID） | 核心问题 | 主要完成证据 |
|---|---|---|
| 范围与判据（`scope`） | 复现哪一版论文、为什么复现、做到多深、允许声称什么？ | 论文身份、复现范围、完成与声明边界 |
| 主张拆解（`claims`） | 到底要检验哪些公式、图表、趋势或机制？ | claim 台账、依赖图、类型化路线 |
| 资源与出处（`resources`） | 所有关键来源、参数和缺失信息是否可追溯？ | 资源清单、哈希、参数出处、歧义清单 |
| 可执行规格（`specification`） | 如何把论文转成无歧义、可运行、可验收的方案？ | 观测量定义、路线规格、claim—运行—证据矩阵 |
| 最小闭环（`pilot`） | 环境、后处理和最小主张路径是否可信？ | 环境锁定、管线测试、pilot 报告 |
| 正式复现（`reproduction`） | 是否按冻结协议执行并保存了完整历史？ | 运行清单、原始结果索引、偏离与重试记录 |
| 对比与验证（`validation`） | 结果是否正确、独立、可比较，差异来自哪里？ | 物理检查、独立验证、可比性审计、逐 claim 裁决 |
| 封装与结论（`release`） | 他人能否审计和重跑，结论有没有越过证据？ | 证据索引、复现包、复现报告和研究者审阅 |

三个类型化规格步骤是可选分支，但一个任务至少应选择其中一个；混合论文可以选择多个：

- 解析理论（`repro-spec-theory`）：假设—引理—公式链、近似阶次、正则化、解析延拓、可控极限和独立推导；
- 模型数值（`repro-spec-model`）：模型、格点与边界、算法、尺寸与扫描、随机性、误差估计、有限尺寸或截断处理；
- 真实材料（`repro-spec-material`）：结构、电子结构方法、赝势或基组、交换关联、k/q 网格、低能子空间、相互作用与双计数、求解器和后处理。

“至少选择一个适用分支”是研究方案与验收责任，不是当前 `optional` 标记自动强制的检查。记录所选分支及其支撑的 claim，并说明未选分支为何不适用；不要无故执行全部分支。模板中的输出文件名是建议的证据产物，勾选步骤不会自动生成文件，也不能证明证据已成立。

## Claim 台账的最小字段

建议 `claim_ledger.csv` 至少包含：

```text
claim_id, paper_location, claim_type, statement, conditions,
target_observable, paper_value_or_pattern, acceptance_rule,
required_evidence, excluded_evidence, status
```

`claim_type` 可以使用 `equation`、`figure`、`table`、`scaling`、`phase_boundary`、`trend`、`mechanism` 或任务定义的其他类型。一个图中若含多个物理主张，应拆成多个 claim；多个图共享同一上游数据时，应在依赖图中显式连接。

## 参数出处与歧义

`parameter_provenance.csv` 中的每项选择建议标记为：

- `explicit`：论文或补充材料明确给出；
- `derived`：可由论文内容无歧义推导；
- `code`：从作者代码或配置提取；
- `cited`：来自论文明确引用的其他来源；
- `inferred`：根据上下文作出的推断；
- `chosen`：本次复现自行选择。

后两类必须给出理由和敏感性风险。关键歧义若会改变目标结论，应进入研究者关口或触发复现范围降级，不能用事后调参掩盖。

## 来源与验证的证据边界

资源阶段按项目内的 [literature-research 协议](../skills/literature-research/SKILL.md)核实论文、补充材料、勘误、作者代码与数据。保留版本或提交号、许可证、访问日期和文件哈希；不能把预印本、正式版本与修订混为同一来源。区分全文核实、仅摘要、仅元数据、推断与未获取来源；二手转述或检索摘要不能替代关键一手证据。缺失信息会改变中心主张时，保留该主张为暂定，并记录受影响的 claim 和下一步。

解析路线需要工具辅助时，按 [theory-derivation 协议](../skills/theory-derivation/SKILL.md)保留可阅读推导、假设、输入、输出和工具版本，并在可行时独立核查关键结论。区分解析结果、计算机辅助推导、数值证据与未验证猜想；有限样本上的成功不等于一般证明。

最小闭环可以用合成数据、已知极限或手算样例测试单位转换、统计、作图与后处理。mock 调度器、API 夹具、测试通过或程序成功退出只能证明所测试的软件行为；它们不能证明真实集群可用、DFT/DMFT 物理正确或论文主张已复现。实际报告分别列出真实通过、失败、未运行和因集群、账户、资源或来源不足而受阻的检查。普通计算后的快速收敛图也不能代替本次冻结协议要求的正式验收。

正式比较先审计版本、方法、参数、单位、有限尺寸、收敛水平、随机与系统误差、数字化误差和后处理定义，再评估差异。保留全部迭代或扫描历史、原始结果和失败检查，不仅保留有利区间或最终图片；独立验证不可得时，明确说明证据相关性与剩余风险。

## 逐主张裁决语义

- 复现：满足预先定义的可比条件和验收规则；
- 部分复现：部分证据成立，但数值、范围、误差或机制链仍有明确缺口；
- 未复现：在可比条件下未满足预定验收规则；
- 条件不足无法判断：来源、参数、数据或方法条件不足以进行公平裁决。

任务或作业“完成”只表示执行状态，不自动产生上述科学裁决。趋势一致、数值一致和机制得到支持是不同证据等级；机制性主张不能仅凭曲线视觉相似或单次拟合宣称成立。

## 建议的 Research Plan 内容

1. 论文身份、复现动机和与当前研究的关系；
2. 复现深度、独立性模式、明确包含项与排除项；
3. 目标 claim 台账及优先级；
4. 类型化方法规格、参数出处和未决歧义；
5. claim—运行—证据矩阵、容差、对照和重复策略；
6. 资源与软件边界、HPC 预算、研究者关口和保护路径；
7. 失败、降级和终止规则；
8. 可对外声明的结论等级与完成证据。

复现中产生的新想法、额外参数扫描和论文之外的科学扩展应进入独立后续任务，避免事后扩大范围并污染原复现裁决。

## 执行、纠错与发布

真实研究任务遵循 [workbench-agent 协议](../skills/workbench-agent/SKILL.md)和[项目指南](../AGENTS.md)。首次执行前，在 Codex 对话中说明 Research Plan、核心 Workflow、Task Spec 的科学承诺、资源、研究者关口和完成证据，展示精确 Confirmed Envelope 及哈希并取得明确确认。Web 用于观察和普通元数据管理，不是授权、提交、取消或对账入口。

确认后可在 Envelope 内自主推进和调整 Working Plan，无需逐命令或逐 Action 审批。普通命令、连接、传输和临时诊断记 Event；正式提交/取消、多运行批次和需要持久溯源的证据验证等科学里程碑记 Action，不为每次尝试添加工作流节点。远程提交、监控与终态清理遵循同一 Agent 协议；提交响应不确定时按已记录作业身份对账，禁止重提探测。

冻结复现协议后的纠错必须记录原因、影响与版本；若扩大科学承诺、方法/软件、资源、权限或保护路径，先通过 researcher 待沟通事项重新确认 Envelope。边界内修正采用最小必要重算，将受影响产物明确标为 `valid`、`suspect`、`invalid` 或 `superseded`，不得静默覆盖出处。连接、环境与传输失败不消耗科学重试额度；替换失败科学计算时显式绑定 `retry_of_action_id` 并遵守 `maxAutomaticRetries`。

发布包应包含可审计推导或代码、环境记录、输入与出处清单、机器可读运行矩阵、原始和处理结果、最小重跑命令及 README。因许可或体积限制不能打包的资源，应保留获取方式、哈希与限制说明。报告按 claim 引用有效证据，区分成功、部分成功、未复现与无法判断，说明偏差和开放问题。最终可对外声称的结论须由研究者审阅确认；Agent 不能自行把运行完成或自己的推断记录为研究者结论。
