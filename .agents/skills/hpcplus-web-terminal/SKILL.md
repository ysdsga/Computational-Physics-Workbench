# HPCPlus Web Terminal

Treat HPCPlus as a single, human-visible terminal transport. Do not navigate or inspect other portal modules.

## Preconditions

Require all of the following:

- The user has manually opened the Edge PWA window titled `HPCPlus平台`.
- The user has manually logged in and connected the web terminal to the intended node.
- No other agent or user is operating the window or clipboard during one command.
- The requested command is short, non-interactive, and produces bounded output.

Do not automate login, CAPTCHA, portal navigation, upload, download, or file-manager actions.

## Command workflow

1. Classify the command with `scripts/HpcPlusBridge.Core.psm1` or run the bridge with `-DryRun`.
2. For a new session, inspect the visible terminal without sending input:

   ```powershell
   powershell -NoProfile -STA -ExecutionPolicy Bypass -File scripts/invoke-hpcplus-web-terminal.ps1 -InspectOnly
   ```

3. Confirm `pwd` before any command that writes files, submits jobs, or changes scheduler state.
4. Ask for explicit action-time confirmation before:
   - submitting a job (`bsub`, `sbatch`, `qsub`);
   - writing, moving, deleting, or changing files;
   - cancelling or modifying a job.
5. Execute exactly one reviewed command. Use `-AllowSubmit` and/or `-AllowMutating` only after the matching confirmation.
6. Read the marker-delimited result and exit status. Stop on timeout, missing markers, terminal disconnection, UI changes, or a 403. Do not retry automatically.

When the workbench has produced and approved a Task Spec, prefer the audited runner. It fetches the exact approved hash, opens a command-run audit record, sends one command, and records `verifying`, `failed`, or `unknown`:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/invoke-hpcplus-task-spec.ps1 -TaskSpecId "spec-id"
```

Use `-PrepareOnly` to inspect the effective `cd -- <cwd> && <command>` without opening an audit run or touching the HPCPlus window.

For LSF submission, the Task Spec must include the complete reviewed script as `execution_payload`. Risk classification and the approval hash cover both the `bsub` command and that payload. Before approval, the user must confirm the remote `.lsf` file is identical to the displayed snapshot.

An approved LSF submission must yield an explicit `Job <id> is submitted` marker. The audited runner registers that ID and moves the Task Spec to `monitoring`; a zero exit code without a job ID becomes `unknown` and is never resubmitted automatically. Query a registered job with:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/poll-hpcplus-lsf-job.ps1 -SchedulerJobRecordId "sched-id"
```

The workbench reserves each poll before terminal access and enforces at least 60 seconds between attempts. The query command is generated by the server, not accepted from the caller.

Read only a bounded log inside the submitted Task Spec directory:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/read-hpcplus-lsf-log.ps1 -SchedulerJobRecordId "sched-id" -RelativePath "dmft.out" -Lines 80
```

The path must be relative and cannot contain traversal, wildcards, or an appended command. The server generates `cd -- <approved cwd> && tail -n N -- <relative path>`, caps output at 200 lines, records an audit event, and enforces a separate 60-second interval.

Example read-only command:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/hpcssh.ps1 -ApprovedWorkingDirectory "/confirmed/project/task/stage" "pwd; hostname"
```

Example submission after explicit confirmation:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/hpcssh.ps1 -ApprovedWorkingDirectory "/confirmed/project/task/stage" -AllowSubmit "bsub < scf.lsf"
```

## Hard limits

- Keep a single command in flight. The bridge enforces a local mutex.
- Keep scheduler polling at least 60 seconds apart.
- Do not run interactive tools such as `vim`, `top`, `htop`, `less`, or installers.
- Do not use `curl`, `wget`, `scp`, `sftp`, `rsync`, SSH, port forwarding, or broad filesystem scans.
- Every executed command requires a separately supplied, normalized approved working directory. Do not change directory inside the reviewed command, use absolute/home-relative paths or `..` traversal, launch detached/background work, or hide actions behind `eval`, `bash -c`, or similar indirect execution. The audited runner changes to the approved Task Spec directory and verifies `$PWD` before the reviewed command. A bound LSF payload may retain one standalone `cd` line only when it exactly equals that same approved directory.
- Do not use the bridge for large output or large file transfer.
- Successful and failed terminal output is capped at 160 lines and 65,536 characters by default; use a bounded `tail` for larger logs.
- Never infer scientific parameters. Review DFT/DMFT inputs and LSF resources separately.

Read [references/protocol.md](references/protocol.md) when diagnosing bridge failures or deciding whether a command fits this transport.
